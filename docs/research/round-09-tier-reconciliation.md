## 1. 调和框架：L1–L6 优先于来源单维

### 1.1 为什么来源不能单独决定层级

R8 两份文档的核心方法论差异：

```
08-core 方法：原生梗优先（三道门）→ 语义是否直接描述游戏行为？
             来源作为辅助维度，仅影响内部产品级（如 L4 P0缺失降B）

08-source 方法：来源 → 产品层级建议（origin_verified 成立 → Primary；
              origin 不成立 → Sub-tag 或降级）
```

08-source 的隐含假设是「来源强 → 产品级高」，但这与 L1–L6 体系矛盾。R7 决策矩阵已明确：**L4（来源可信）是 L3 的下级维度，不具有独立否决权**。来源弱只影响 L4 层判定（产品级封顶 B），不影响 L1/L2/L3/L5 的通行。

### 1.2 本轮的调和准则

```
对每项候选称号，依次通过 L1–L6：

L1 安全红线 ──── ❌ → 🔴 安全禁用（不可挽救）
      ✅
L2 可计算性 ──── ❌ → ⬛ 数据门槛淘汰
      ✅         ⚠️ → 🟡 产品级降级（代理弱/外部依赖）
      ✅
L3 语义保真 ──── 三道门裁决 → 决定层级归属（核心/实验/禁用）
      ✅         SF评分 → 决定产品级（A/B）
      ✅
L4 来源可信 ──── ✅ → 🟢 Verified Origin 徽标，不限制产品级
      ✅         ⚠️ → 🟡 Partial Origin 徽标，产品级最高 A（不封顶）
      ✅         ❌ → 🟠 Community Consensus 徽标，产品级最高 A（语义强可抵消）
      ✅         🔵 → 🔵 Unverifiable 徽标（tool_unavailable），同❌处理
      ✅
L5 认知度 ────── ❌ <60% → 淘汰 trigger 或降级
      ✅         ⚠️ 60–75% → 产品级最高 B
      ✅
L6 传播力 ────── tiebreaker only（同级PK时使用）
```

**关键声明**：
- L4 来源弱**不自动禁止**该称号进入任何层级
- 来源弱的影响：**证据徽标降级 + 在产品文案中注明「社区共识，起源待验证」**
- 只有 L1（安全红线）和 L3-门2（脱离选手后零语义残余）能触发**禁用层**
- L2 不可计算触发**数据门槛淘汰**（不是禁用——未来数据可用时可恢复）

## 2. 三种淘汰类型的明确定义

在整个 R1–R8 的探索中，"淘汰/禁用"被混用。R9 统一为三种类型：

### 2.1 安全禁用（Safe Disable）

| 属性 | 定义 |
|:-----|:-----|
| **触发条件** | L1 安全红线不通过 |
| **判定维度** | 外貌攻击 / 人格侮辱 / 国籍种族 / 私生活 / 官方警告 / 法律风险 |
| **可恢复性** | 🔴 **不可恢复**。即使未来社区接受度变化，产品不应冒险 |
| **示例** | 马头(H1外貌)、CJB(H1人格)、精忠报国(H1国籍)、洗澡狗(H1人格) |
| **处理方式** | 完全从产品中移除，不保留任何引用 |

### 2.2 语义淘汰（Semantic Elimination）

| 属性 | 定义 |
|:-----|:-----|
| **触发条件** | R8 三道门-门2 失败：脱离原选手后字面语义不携带任何游戏行为含义 |
| **判定维度** | 人物外号 → 纯社区知识依赖 → 零独立语义残余 |
| **可恢复性** | 🟡 **不可恢复（语义层面）**。梗的语义本质是选手绑定，无法通过补数据改变 |
| **示例** | 厂长("工厂管理者"无打野语义)、灯皇("灯之皇"无ADC语义)、接Q辣舞(ID谐音零语义) |
| **处理方式** | 移除 trigger，保留为 aliases 引用彩蛋。**禁止去梗化替代** |

### 2.3 数据门槛淘汰（Data Threshold Elimination）

| 属性 | 定义 |
|:-----|:-----|
| **触发条件** | L2 可计算性不通过：核心语义需要的字段不可获取且无合理简化方案 |
| **判定维度** | 字段不可获取 / 代理强度极弱 / 外部数据源依赖无保障 |
| **可恢复性** | 🟢 **可恢复**。如果未来获得所需数据（事件级数据、新API字段），可重新评估 |
| **示例** | 翻山(opponent_rank不可获取 → R6淘汰)、永不团灭(团灭事件数据未确认 → PENDING) |
| **处理方式** | 标记为 PENDING_DATA，不进入当前产品层。保留候选池 |

### 2.4 淘汰类型对照

| 淘汰类型 | 触发层 | 可恢复 | 保留方式 | 典型条目 |
|:--------|:-----:|:-----:|:--------|:--------|
| 🔴 安全禁用 | L1 | ❌ 不可恢复 | 完全移除 | 马头/CJB/精忠报国 |
| 🟠 语义淘汰 | 三道门-门2 | ❌ 不可恢复 | aliases引用彩蛋 | 厂长/灯皇/接Q辣舞 |
| 🟡 数据门槛淘汰 | L2 | ✅ 可恢复 | PENDING_DATA候选池 | 翻山 |

## 3. 证据徽标体系：来源弱如何体现

### 3.1 四级徽标

来源弱**不自动禁止**，但必须通过徽标在产品文档和内部沟通中显式标注：

| 徽标 | L4 判定 | 含义 | 对产品级的影响 |
|:----:|:------:|:-----|:-------------|
| 🟢 **Verified Origin** | origin ✅ + meaning ✅ | 起源可定位至P0/P1比赛录像或官方出品 | 无限制。可标注「起源已验证」 |
| 🟡 **Partial Origin** | origin ⚠️ + meaning ✅ | 起源未确认（仅有P3社区共识），但语义经多源交叉验证确认 | 产品文案标注「社区共识」。不封顶产品级 |
| 🟠 **Community Consensus** | origin ❌ + meaning ✅ | 起源不可验证（tool_unavailable/无P0首创时刻），但社区共识确认语义 | 产品文案标注「社区起源」。产品级不受限但需更高自嘲开关灵敏度 |
| 🔵 **Unverifiable** | origin ❌ + meaning ⚠️ | 起源和语义均无法通过可访问来源验证（全部tool_unavailable） | ⚠️ 产品级最高 B sub_tag。需用户验证确认理解度。禁止作为 primary |

### 3.2 徽标 ≠ 层级

```
徽标是「我们对这个梗知道多少」的标注，不是「这个梗该在哪一层」的裁决。

层级由 L1–L6 综合判定，其中：
- L3（语义保真）决定核心/实验/禁用
- L2+L5 决定产品级（primary/sub_tag/C）
- L4 提供徽标，仅在极端情况下（🔵 Unverifiable）封顶产品级
```

## 4. 核心层 origin 未验证项的保留规则

### 4.1 问题

08-core 核心层 7 项中，5 项 origin 未验证或仅 P3：

| 核心层条目 | origin | meaning | 产品级 |
|:----------|:------:|:------:|:-----:|
| 天神下凡 | ✅ P0+P1 | ✅ | A primary |
| 4396 | ✅ P0+P1+P2+P3 | ✅ | B primary |
| 奇迹行者 | ⚠️ P0缺失, P3三源 | ✅ | B sub_tag |
| 正方形打野 | ⚠️ P0缺失, P3 | ✅ | B sub_tag |
| 护国神牛 | ⚠️ P3 only | ✅ | B sub_tag |
| 疯牛病 | ⚠️ P3 only | ✅ | B sub_tag |
| 勾股定理 | ⚠️ P3 only | ✅ | B sub_tag |

**问题**：核心层中 5/7 项 origin 未验证。这些项是否可以保留在核心层？

### 4.2 裁决规则

> **核心层的准入门槛 = 原生行为语义（三道门-门1），非来源质量。**

核心层与实验层的分界线定义（R8 §9.2）：

```
核心层：不需要知道"谁"才能理解梗。梗本身就是行为描述。
实验层：部分需要。但字面中有独立锚点可以减少对"谁"的依赖。
禁用层：完全需要。脱离"谁"之后梗消失。
```

这个分界线是**语义判定**，与来源质量无关。一个梗即使起源不可考（如社区自然形成的英雄行为梗），只要其字面语义直接描述游戏行为，就应进入核心层。

### 4.3 来源弱在核心层内的处理

核心层 ≠ 所有项平等。来源弱通过以下方式在核心层内部体现：

| 来源质量 | 核心层内产品级封顶 | 徽标 | 文案要求 |
|:-------|:---------------:|:----:|:--------|
| origin ✅ | A primary | 🟢 Verified Origin | 可引用原始比赛/选手 |
| origin ⚠️ + meaning ✅ | **B sub_tag**（不封顶但当前均为B） | 🟡 Partial Origin | 标注「社区共识」 |
| origin ❌ + meaning ✅ | B sub_tag | 🟠 Community Consensus | 标注「社区起源」 |
| origin ❌ + meaning ⚠️ | **不应进入核心层** | 🔵 Unverifiable | 语义本身不可验证 → 退至实验层 |

**理由**：核心层的信任基础是「梗的语义直接描述游戏行为」。如果语义本身无法验证（meaning ⚠️），那"原生行为梗"的前提就不成立。但如果语义已验证（meaning ✅），起源不可考不影响「梗在当下是否描述游戏行为」这一事实。

### 4.4 应用到当前核心层

| 条目 | 当前产品级 | origin | 裁决 |
|:-----|:--------:|:------:|:-----|
| 天神下凡 | A primary | ✅ | ✅ 保留。核心层旗舰 |
| 4396 | B primary | ✅ | ✅ 保留 |
| 奇迹行者 | B sub_tag | ⚠️ | ✅ 保留。origin ⚠️ 已体现为产品级 B sub_tag |
| 正方形打野 | B sub_tag | ⚠️ | ✅ 保留。同上 |
| 护国神牛 | B sub_tag | ⚠️ | ✅ 保留。同上 |
| 疯牛病 | B sub_tag | ⚠️ | ✅ 保留。同上 |
| 勾股定理 | B sub_tag | ⚠️ | ✅ 保留。同上。传播力低视为L6 tiebreaker |

**结论**：当前核心层 7 项全部满足保留条件。不需要将 origin ⚠️ 项驱逐出核心层——它们进入核心层的原因是「语义直接描述游戏行为」（护国神牛 = 牛头保护开团，疯牛病 = 牛头乱开团，勾股定理 = 钩子精准），而非来源质量。

## 12. 结论

### 12.1 本轮核心贡献

1. **确立了 L1–L6 为调和框架**：来源（L4）是六维之一，不单独决定层级。终结了 08-source 中「来源弱 → 降产品级」的单维推理。
2. **来源弱 ≠ 自动禁止**：通过四级证据徽标（🟢🟡🟠🔵）在产品文档中显式标注来源信任度，不影响层级资格。
3. **三种淘汰类型明确定义**：安全禁用（L1，不可恢复）、语义淘汰（三道门-门2，不可恢复）、数据门槛淘汰（L2，可恢复）。结束了 R1–R8 中"淘汰/禁用"混用的混乱。
4. **核心层 origin 未验证项的保留规则**：核心层准入门槛 = 原生行为语义，非来源质量。origin ⚠️ 可保留（产品级封顶 B），origin ❌ + meaning ⚠️ 不可进入核心层。
5. **六项调和完成**：
   - 世一上/绝食流/红温 三维持 sub_tag（拒绝 08-source Primary 建议）
   - 纳尔圣经/拉扯圣经 下调为 sub_tag（L2可计算性 / L4来源双重降级）
   - 暴毙AD 维持 A primary（L1–L3全绿 + L5高认知度抵消来源弱）
6. **证据徽标首次分配**：17/20 产品卡获得来源信任标注。

### 12.2 分层 v2 一句话总结

> **核心层 7 项不变（原生行为语义为准入，非来源质量）。实验层 13 项中纳尔圣经/拉扯圣经内部产品级下调为 sub_tag（L2+L4双重约束），暴毙AD维持 A primary（语义自明度抵消来源弱）。证据徽标体系首次标注全部产品卡的来源信任度。拉扯圣经 🔵 Unverifiable 为当前最大风险——人工补证是 R10 最高优先级行动。**
