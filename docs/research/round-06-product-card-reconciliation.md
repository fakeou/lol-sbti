## 1. 核心修订裁决（5 项必执行）

### 1.1 移除：翻山（#25）→ ❌ 淘汰

| 维度 | 证据 |
|------|------|
| **Round 4 字段审计 (M1)** | §3.4 A-ANY-04 翻山 → ❌ 淘汰。需要 `opponent_rank` 和 `rank` 变化数据。"下克上"是核心触发条件，不可移除。`main.rs` CsvMatch 及 UploadMatchV1 均不含 rank/opponent_rank。 |
| **Round 5 打野冲突 (J5)** | §5.2 CG-01 移除操作：翻山/骑士归来/北伐 三项因依赖不可获取字段正式移除。CG-01 从 5 成员缩减为 2（不破不立+涅槃）。 |
| **产品卡残留 (P5)** | §6 产品卡 #25 翻山仍然存在，含完整触发规则和文案。与上述两处淘汰结论**矛盾**。 |
| **裁决** | **从产品卡中移除 #25 翻山。** 不可降级为 status——"下克上"语义不可脱离 opponent_rank 代理。淘汰后不产生新的行为覆盖缺口（本身不可计算）。 |

### 1.2 降级：雷达哥（#09）→ B sub_tag

| 维度 | 证据 |
|------|------|
| **产品卡现状 (P5)** | §2 #09 雷达哥标注"纯褒义，A级可直接上线""本批次最安全的称号之一" |
| **Round 5 打野冲突 (J5)** | §2 语义代理降级裁决：A primary → **B sub_tag**。理由：(1) 核心语义"预判对手位置"的代理 `vision_score` 为**中等强度代理**，不及奇迹行者的 `kill_participation`（强代理）；(2) `deaths < P25` 的"反打野预判"含义为**弱代理**；(3) 辅助证据 `kill_participation > P65` 与宁王/我就是天重叠，区分度不足 |
| **代理强度评估** | vision_score（中代理：插眼多≠预判准）+ deaths（弱代理：低死亡可能只是怂）+ kill_participation（弱代理：高参团也可能是无脑打架） |
| **裁决** | **雷达哥降为 B 级 sub_tag。** 产品层级从 primary → sub_tag。展示名仅使用"雷达哥"，禁止"窥屏打野"。触发时 UI 附"野区意识出色"文案。若未来获得事件级数据（反蹲成功率），可重新评估升级。 |

### 1.3 YYDS / 永远滴神（#23）→ status（非 product card）

| 维度 | 证据 |
|------|------|
| **产品卡现状 (P5)** | §6 #23 YYDS 作为完整产品卡呈现（主称号触发组合 + 副标签 + 近期状态 + 为什么是你），语义为 primary |
| **Schema 冲突裁决 (M2)** | §3.1 明确裁决：**`product_tier = status`**。理由：(1) "永远滴神"原始语境是**实时惊叹**（山泥若看比赛时喊出），非长期画像标签；(2) YYDS 已高度泛化（out_of_circle），LOL 专属区分度低；(3) 与天神下凡分工：天神下凡=长期 carry 风格(primary)，YYDS=单场碾压高光(status) |
| **funnel 原始分级 (M3)** | A-ANY-02 列为 A 级 primary → 被 M2 §3.1 裁决推翻 |

### 1.4 右手：评估降别名/淘汰

| 维度 | 证据 |
|------|------|
| **产品卡现状 (P5)** | §3 #12 左手/右手合并为一张产品卡。副标签"世另我"：当数据条件满足时，**随机在"左手"和"右手"之间切换**——致敬 Knight 和 Chovy 的镜像关系 |
| **用户验证风险 (V5)** | §8.3 右手梗特殊风险：(1) 中文圈对 Chovy 认知度远低于 Knight → 右手梗底层支撑更弱；(2) 中文歧义——"右手"有"得力助手"等含义，易误读；(3) LCK 文化隔阂——右手梗是 LPL 观众对 LCK 选手的"镜像命名"，LCK 观众不认可；(4) **假设 H-18**：右手梗总体理解正确率 < 60%（已到 T6 下线阈值），分享意愿可能 < 3.0 |
| **"随机复用左手触发"问题** | 产品卡 #12 的"世另我"标签设计为：数据条件满足时随机在"左手"和"右手"之间切换。这等价于**右手完全复用左手的触发条件**——二者使用相同的 `cs_per_min > P80 + damage_per_min > P75` 门槛。但左手和右手在社区认知中不是等价的——左手有独立梗基础（Knight 左撇子+操作细腻），右手是衍生/镜像梗（无独立语义基础，纯粹是"Chovy=Knight的镜像"）。随机复用触发条件 = 将"衍生梗"伪装成"独立梗"。 |
| **裁决** | **(a) 右手不得作为独立触发称号。** 移除"世另我"随机切换逻辑。右手不再作为可触发的 product title_type（无论 primary/sub_tag/status）。(b) 右手保留为**左手产品卡中的解释性别名**（aliases 字段），不参与触发逻辑——即产品层仅在"圈内梗解释"中出现一次"Chovy 被镜像称为'右手'"，不展示给用户作为称号。(c) 左手单独作为 primary 称号上线。 |
| **理由** | 右手缺乏独立梗基础（仅为镜像衍生），认知度预测 <60%（低于淘汰线），中文歧义风险高。若未来 Chovy 在中国社区产生独立梗（非 Knight 镜像），可重新评估。 |
