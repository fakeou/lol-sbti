## 1. 为何 20 梗不能做全因子设计

### 1.1 全因子的维度爆炸

Round-05 §0.1 定义了四层用户分层：

| 维度 | 水平数 | 水平 |
|------|:------:|------|
| 游戏经验 | 2 | 老玩家(≥3年) / 新玩家(<3年) |
| 位置 | 5 | Top / Jungle / Mid / ADC / Support |
| 内容消费习惯 | 4 | 赛事观众 / 主播观众 / 双修 / 都不怎么 |
| 自嘲模式 | 2 | 开启 / 关闭(默认) |

**全因子交叉** = 2 × 5 × 4 × 2 = **80 个格子 (cells)**

如果每个格子需要最小 30 份有效样本（社会心理学常规底线），则：

```
每梗所需最小样本 = 80 cells × 30 = 2,400 份
20 梗全因子总计   = 20 × 2,400 = 48,000 份
```

这不可行。即便放宽到 20 份/cell：

```
20 梗 × 80 × 20 = 32,000 份 — 仍然不可行
```

### 1.2 实用简化：主效应模型替代全因子

**结论：不对 position × content_consumption × self_mock 做全交叉。**

改为**边际分层 + 关键交互专项测试**：

| 分析层级 | 交叉维度 | 格子数 | 用途 |
|----------|----------|:------:|------|
| **层级 A（主分析）** | 游戏经验 × 自嘲开关 | 2×2 = **4 cells** | 所有梗的主效应检测 |
| **层级 B（位置专项）** | 位置 × 游戏经验 | 5×2 = **10 cells** | 仅位置绑定梗（如左手→mid，奇迹行者→jungle）做跨位误读检测 |
| **层级 C（内容消费）** | 内容消费习惯 | **4 cells** | 作为协变量进入回归，不要求每格独立检验 |

**简化后每梗所需最小样本**：

- 层级 A（所有 20 梗）：4 cells × min 25 = **100 份/梗**（边际分层）
- 层级 B（仅位置绑定梗，约 8 梗）：10 cells × min 15 = 150 份/梗
- 层级 C：不做独立 cell 检验，用回归控制

**20 梗总样本 ≈ 20 × 100 + 8 × 50(增量) ≈ 2,400 份**（按层级 A 主设计）。

### 1.3 审计反馈驱动的简化理由

Round-03 审计 GAP-P1 指出打野位严重短缺——这意味着**按 position 做全交叉的部分 cell（如 jungle × 新玩家 × 主播观众 × 自嘲关）几乎不可能填满**。与其在空 cell 上浪费配额，不如用层级 B 只覆盖有意义的交互。

## 2. 统计功效框架

### 2.1 核心测试的统计模型

| 测试 | 因变量类型 | 统计模型 | 效应量指标 |
|------|:----------:|----------|:----------:|
| **T1 理解正确率** | 二项（正确/错误） | 单样本二项比例检验 / 两样本比例差 | 正确率 p |
| **T2 冒犯率** | 二项（冒犯/未冒犯） | 单样本二项比例检验 | 冒犯率 p |
| **T3 分享意愿** | 连续（Likert 1–7） | 单样本 t 检验 / 两独立样本 t | Cohen's d / 均值差 |
| **分层比较** | 二项比例差 | 两样本比例差检验（正态近似/Fisher exact） | Δp |

### 2.2 通用符号

| 符号 | 含义 | 本方案默认值 |
|:----:|------|:-----------:|
| α | 第一类错误率（假阳性） | 0.05（单侧） |
| β | 第二类错误率（假阴性） | 0.20（→ power = 1−β = 80%） |
| δ | 最小可检测效应量（ clinically meaningful ） | 见 §2.3–§2.5 |
| n | 每梗所需有效样本 | 见 §3 三档方案 |
| FWER | 族错误率（family-wise error rate） | ≤ 0.05（多重检验校正后） |

### 2.3 T1 理解正确率：二项比例功效

**决策场景**：检测某梗的理解正确率是否低于 60%（下线阈值）。

**假设**：
- H₀: p ≥ 0.60（梗可理解）
- H₁: p < 0.60（梗不可理解，应降级/淘汰）
- 最小可检测效应量 δ = 10pp（即实际 p = 0.50 时可检测到显著偏离 0.60）

**单样本二项检验功效公式**（正态近似）：

```
n = [z_α × √(p₀(1−p₀)) + z_β × √(p₁(1−p₁))]² / δ²

其中：
  p₀ = 0.60（H₀ 边界）
  p₁ = 0.50（H₁ 真实值）
  δ  = 0.10
  z_α = 1.645（单侧 α=0.05）
  z_β = 0.842（power=80%）

n = [1.645×√(0.24) + 0.842×√(0.25)]² / 0.01
  = [1.645×0.4899 + 0.842×0.5]² / 0.01
  = [0.8059 + 0.421]² / 0.01
  = 1.2269² / 0.01
  = 1.5053 / 0.01
  ≈ 151
```

**结论**：检测 10pp 的理解正确率下降需要 **n ≥ 151** 份/梗。

| 可检测 δ | 所需 n（α=0.05, β=0.20） | 适用场景 |
|:--------:|:------------------------:|---------|
| 15pp | 67 | 粗略筛选——区分"明显不懂"和"基本懂" |
| **10pp** | **151** | **标准决策——能否通过 60% 阈值** |
| 5pp | 600 | 精确比较——区分 60% 和 65% |

### 2.4 T2 冒犯率：二项比例功效（核心指标）

**决策场景**：检测某梗的冒犯率是否超过红色下线阈值。

**假设**：
- H₀: p ≤ 0.10（冒犯率可接受，绿色/黄色区）
- H₁: p ≥ 0.15（冒犯率不可接受，红色区）
- δ = 5pp（从 10% → 15% 的跃迁）

```
p₀ = 0.10, p₁ = 0.15, δ = 0.05

n = [1.645×√(0.10×0.90) + 0.842×√(0.15×0.85)]² / 0.05²
  = [1.645×0.3 + 0.842×0.3571]² / 0.0025
  = [0.4935 + 0.3007]² / 0.0025
  = 0.7942² / 0.0025
  = 0.6307 / 0.0025
  ≈ 252
```

**结论**：检测 5pp 的冒犯率升高需要 **n ≥ 252** 份/梗。

**更精细的可检测效应量**：

| 可检测 δ | 所需 n（α=0.05, power=80%） | 解读 |
|:--------:|:---------------------------:|------|
| 10pp（10→20%） | 63 | 粗筛——高敏感梗快速淘汰 |
| **5pp（10→15%）** | **252** | **标准决策——通过/不通过红色阈值** |
| 3pp（10→13%） | 702 | 精确监控——灰度上线后持续追踪 |

**关键洞察**：Round-05 提出的"每梗 ≥ 100 份"（§3.2）在 α=0.05, power=80% 下只能检测 **δ ≈ 8pp** 的冒犯率差异。这意味着如果某梗的真实冒犯率从 10% 上升到 18%，100 份样本可以检测到；但如果只上升到 14%（仍在黄色区边界），100 份样本的 power 仅有 ~45%——**有一半以上概率漏判**。

### 2.5 T3 分享意愿：连续因变量功效

**决策场景**：检测分享意愿指数是否低于 3.0（下线阈值）。

**假设**：
- 分享意愿为 Likert 7 点，假设总体 SD ≈ 1.8（基于类似产品研究）
- 最小可检测均值差 Δ = 0.5 分（从 3.5 → 3.0）
- Cohen's d = 0.5 / 1.8 ≈ 0.278（小到中效应）

**单样本 t 检验功效**（近似）：

```
n = (z_α + z_β)² × (σ/Δ)²
  = (1.645 + 0.842)² × (1.8/0.5)²
  = 2.487² × 3.6²
  = 6.185 × 12.96
  ≈ 80
```

**结论**：检测 0.5 分的分享意愿下降需要 **n ≥ 80** 份/梗。

**更实际的场景（两样本比较，如自嘲组 vs 默认组）**：

```
n_per_group = 2 × (z_α + z_β)² × (σ/d_effect)²
            = 2 × 6.185 × (1.8/0.5)²
            ≈ 160 per group
```

## 3. 多重检验校正：20 梗的 FWER 控制

### 3.1 问题量化

20 个梗独立检验时（每个梗做一次冒犯率显著性检验）：

```
FWER = 1 − (1 − α)^20
     = 1 − (0.95)^20
     = 1 − 0.3585
     ≈ 0.6415
```

**即使用名义 α=0.05，至少有一个梗被错误标红的概率为 64%。** 这在产品决策中不可接受——每三轮测试就可能有一轮误杀一个安全梗。

### 3.2 校正方案

| 方法 | α 调整 | 保守程度 | 适用场景 |
|------|:------:|:--------:|----------|
| **Bonferroni** | α' = 0.05/20 = 0.0025 | 最保守 | 高风险决策（下线判定） |
| **Holm-Bonferroni** | 逐步：α/(20), α/19, α/18... | 中等保守 | 标准方案（推荐） |
| **Benjamini-Hochberg (FDR)** | 控制错误发现率 q=0.05 | 较宽松 | 探索/筛选阶段 |
| **分层检验** | 先全局 F 检验，通过后才做单梗检验 | 最不保守但需预先分组 | 梗聚类后使用 |

### 3.3 推荐方案：双轨校正

```
第一轨（安全性决策——下线/不通过）：
  使用 Holm-Bonferroni，α_family = 0.05
  → 样本量按 Bonferroni 最坏情况设计

第二轨（探索性决策——筛选/排序）：
  使用 Benjamini-Hochberg FDR，q = 0.10
  → 允许更多假阳性，因为后续会有验证轮
```

### 3.4 校正后的样本量膨胀

以 T2 冒犯率为例（原 n=252 for α=0.05）：

| 校正方法 | α' | z_α' | 校正后 n | 膨胀因子 |
|----------|:--:|:----:|:--------:|:--------:|
| 无校正 | 0.05 | 1.645 | 252 | 1.0× |
| Holm（最坏格） | 0.0025 | 2.807 | **523** | 2.07× |
| Bonferroni | 0.0025 | 2.807 | **523** | 2.07× |
| BH-FDR（探索） | ~0.025 | 1.960 | 316 | 1.25× |

**关键结论**：使用严格的多重检验校正后，每梗所需样本从 252 增加到约 **523**。这就是"20 梗不能全要"的统计根源——不仅是全因子设计的格子爆炸，还有多重检验校正导致的样本量膨胀。

## 4. 置信区间校准：点估计的不可靠性

### 4.1 二项比例的 Wilson 置信区间

Round-05 的下线阈值（如"冒犯率 > 15% → 红色"）是**点估计决策**——但点估计在小样本下极不稳定。应改为**置信区间下限决策**。

#### Wilson Score Interval（小样本下优于 Wald）：

| n | 观测冒犯率 | 95% Wilson CI | CI 宽度 | 能否确定过线？ |
|:--:|:---------:|:-------------:|:-------:|:-------------:|
| 50 | 10% (5/50) | [4.3%, 21.4%] | 17.1pp | ❌ 太宽 |
| 50 | 16% (8/50) | [8.3%, 28.5%] | 20.2pp | ❌ 太宽 |
| 100 | 10% (10/100) | [5.5%, 17.4%] | 11.9pp | ⚠️ 上界过 15% |
| 100 | 16% (16/100) | [10.1%, 24.4%] | 14.3pp | ⚠️ 下界低于 15% |
| 200 | 10% (20/200) | [6.6%, 14.9%] | 8.3pp | ✅ 上界低于 15% |
| 200 | 16% (32/200) | [11.6%, 21.7%] | 10.1pp | ⚠️ 下界仍低于 15% |
| 250 | 10% (25/250) | [6.9%, 14.3%] | 7.4pp | ✅ 窄 |
| 250 | 16% (40/250) | [12.0%, 21.1%] | 9.1pp | ⚠️ 下界低于 15% |
| 400 | 10% (40/400) | [7.4%, 13.3%] | 5.9pp | ✅ 窄 |
| 400 | 16% (64/400) | [12.7%, 19.9%] | 7.2pp | ⚠️ 下界接近 15% |
| 500 | 10% (50/500) | [7.7%, 12.9%] | 5.2pp | ✅ 窄 |
| 500 | 16% (80/500) | [13.0%, 19.5%] | 6.5pp | ✅ 边界清晰 |

#### 决策规则（替代 Round-05 T6 的点估计阈值）：

```
决策 = IF 观测冒犯率 95% CI 下限 > 15% → 立即下线（RED）
       IF 观测冒犯率 95% CI 上限 < 10% → 安全（GREEN）
       ELSE → 需要更多数据（YELLOW — 继续收集）
```

**若要 95% CI 宽度 ≤ 10pp（在 p≈10% 附近），需要 n ≥ 200**。若要宽度 ≤ 5pp，需要 n ≥ 550。

### 4.2 分享意愿均值的 CI

Likert 7 点，假设 SD=1.8：

| n | 95% CI 半宽（±） |
|:--:|:----------------:|
| 50 | ±0.50 |
| 80 | ±0.39 |
| 100 | ±0.35 |
| 200 | ±0.25 |
| 400 | ±0.18 |

若检测"分享意愿 < 3.0"（下线阈值），n=100 时 95% CI 为 3.0 ± 0.35 = [2.65, 3.35]——过于宽泛，无法确定是否真的低于 3.0。

## 5. 三档方案：低成本 / 标准 / 高置信

### 5.1 方案总览

| 参数 | 低成本（Screening） | 标准（Decision） | 高置信（Publication） |
|:-----|:-------------------:|:----------------:|:---------------------:|
| **用途** | 快速淘汰明显问题梗，筛选候选 | 产品上线/下线决策 | 可公开发表的证据 |
| **每梗样本量 (n)** | **100** | **250** | **500** |
| **α 水平**（单梗） | 0.10 | 0.05 | 0.0025（Bonferroni） |
| **多重检验校正** | BH-FDR q=0.10 | Holm-Bonferroni | Bonferroni（α_family=0.05） |
| **Power @ δ=5pp(冒犯)** | ~45%（不足） | 80% | ~77%（接近80%） |
| **最小可检测 δ @ power=80%** | 8pp | 5pp | 5pp |
| **95% CI 宽度（p=10%）** | ±7.5pp (Wald) | ±4.5pp | ±3.0pp |
| **每梗每层最小 n（层级A 4格）** | 25 | 50 → 部分格只做描述 | 60 → 部分格只做描述 |
| **总样本（20梗，层级A）** | 2,000 | 5,000 | 10,000 |
| **总样本（含位置专项8梗）** | 2,400 | 5,800 | 11,600 |
| **预估成本**（市场调研参考） | ¥30,000–60,000 | ¥80,000–150,000 | ¥180,000–300,000 |
| **测试周期** | 1–2 周 | 2–4 周 | 3–5 周 |

> **成本参考**：基于中国游戏行业问卷调研均价 ¥30–60/有效份（有配额分层溢价 50–100%）。

### 5.2 低成本方案详情（Screening）

**定位**：不是替代标准方案，而是**在标准方案之前做一次粗筛**，把 20 梗中明显有问题的先淘汰，让标准方案的 250 份/梗花在"真的有争议"的梗上。

**设计**：
- n = 100/梗，20 梗 = 2,000 份
- α = 0.10（放宽——宁可误杀，不能漏过）
- BH-FDR q = 0.10
- 只跑 T1（理解正确率）+ T2（冒犯率），不跑 T3/T4/T5
- 层级 A（4 cells），不跑层级 B 跨位置

**能做什么**：
- ✅ 快速识别冒犯率 > 20% 的明显问题梗（如马头、及时雨送姜对照组）
- ✅ 快速识别理解正确率 < 45% 的认知灾难梗
- ✅ 将 20 梗排优先级→选出 12–15 个进入标准方案
- ❌ **不能**用于产品上线/下线决策——CI 太宽，power 不足

**不能做什么**：
- ❌ 不能区分 10% vs 15% 冒犯率（power≈35%）
- ❌ 不能稳定检测自嘲开关的非单调效应
- ❌ 不能做跨位置误读分析

### 5.3 标准方案详情（Decision）

**定位**：产品上线/下线决策的核心数据集。

**设计**：
- n = 250/梗，12–15 梗（低成本筛后）= 3,000–3,750 份
- α = 0.05，Holm-Bonferroni 校正
- power = 80% @ δ=5pp（冒犯率从 10%→15%）
- 层级 A（4 cells）+ 层级 B（8 梗跨位置）+ 层级 C（协变量）
- 跑 T1 + T2 + T3（三套问卷可同批用户填，用 Latin square 控制疲劳）
- T4/T5 需额外样本（见 §6.3）

**关键指标的可检测精度**：

| 指标 | 可检测效应 | Power | CI 精度 |
|------|:----------:|:-----:|:-------:|
| 冒犯率差异 | 5pp | 80% | ±4.5pp |
| 理解正确率差异 | 10pp | 85% | ±7.5pp |
| 分享意愿差异 | 0.5 分 | 85% | ±0.22 分 |
| 自嘲 vs 默认差异（冒犯率） | 8pp | 70% | ±8pp |

**注意**：250 份/梗分配到层级 A 的 4 个 cell，每 cell ≈ 62.5 份。这足以估计每 cell 的冒犯率（CI ≈ ±7pp），但不足以在每 cell 内做显著性检验。**cell 级分析是描述性的，不做推断。**

### 5.4 高置信方案详情（Publication）

**定位**：可公开发表、可复现、高统计严格度的数据集——适合在公司内部评审、对外 PR 防御、或学术合作中使用。

**设计**：
- n = 500/梗，12–15 梗 = 6,000–7,500 份
- α_family = 0.05，Bonferroni 校正（每梗 α' = 0.0025）
- power ≈ 77% @ δ=5pp（略低于 80% 目标；精确 n=523 可达 80%，500 为整数取整）
- 层级 A（4 cells，每 cell ≥ 60）+ 层级 B（8 梗跨位置，每 cell ≥ 30）+ 层级 C（完整协变量回归）
- 预注册分析计划，避免 p-hacking

**额外能力**：
- ✅ 可以检测到 5pp 的冒犯率差异且族错误率 FWER ≤ 0.05
- ✅ 95% CI 足够窄（±3.0pp at p≈10%），可以对外声称"冒犯率不高于 X%"
- ✅ 可以检验自嘲开关的非单调效应（需要 ≥ 100/cell，层级 A 的 4 格每格 125 份满足）
- ✅ 可以做亚组分析（如"老玩家 × 赛事观众 × 自嘲开"的子群）
- ⚠️ 检测 3pp 差异需要更大的 n（约 1,200/梗），超出本方案范围

## 6. 专项校准：自嘲开关的真实灰度问题

### 6.1 Round-05 的根本缺陷

Round-05 §6 的自嘲开关验证方法存在一个致命缺陷：

> **问卷中说"假设你开启了自嘲开关" ≠ 真实开关体验。**

原因：
1. **假设场景没有社交成本**：用户在被问"假设你开启了自嘲"时，没有真实的社交后果——他们不会真的在朋友圈展示 4396
2. **自嘲是行为而非态度**：真正的自嘲开关效果体现在"用户是否真的愿意展示"（行为），而非"用户是否说愿意"（态度）
3. **非单调效应需要真实反事实**：H2 假设（"我已自嘲了系统还嘲笑我太过分"）只有在用户**真正收到**一个 B 级梗时才可能触发——问卷中用户看到 4396 时的反应 ≠ 被系统授予 4396 时的反应

### 6.2 问卷层可做的最大努力

在问卷阶段，自嘲开关只能做**态度层模拟**，且必须明确标注：

```
标注：以下自嘲开关相关数据为「态度模拟」，
      不代表真实产品中的行为。真实灰度验证需在 Phase 4（灰度上线）完成。

分析时使用的标签：
  - self_mock_simulated = "模拟自嘲开启"（问卷中告知"假设你开启了自嘲"）
  - self_mock_simulated_off = "模拟自嘲关闭"（默认提问，不提及自嘲）
  
  → 绝不可标注为 self_mock_real
```

**态度模拟的验证价值**：
- ✅ 可以探测态度层差异的方向（开启自嘲的人在态度上是否更宽容）
- ✅ 可以验证 T2 测试工具本身是否对自嘲状态敏感
- ❌ **不能**作为产品决策中"自嘲开关有效"的证据
- ❌ **不能**用于标定自嘲开关的阈值

### 6.3 真实灰度验证的最低可行方案

真实自嘲开关验证需要 Phase 4 产品内 A/B 测试：

```
Phase 4-A：小规模灰度（3–5% 用户，n≥2,000 真实用户）
  - 随机分配：A 组（默认关闭自嘲）/ B 组（默认开启自嘲）
  - 只展示 3 个正面 A 级梗 + 2 个 B 级梗
  - 观察指标：真实投诉率、称号更换率、自嘲开关关闭率
  - 周期：2 周

Phase 4-B：自嘲开关的非单调效应验证
  - 选取 B 级梗 4396 和红温
  - 交叉设计：自嘲开/关 × 正面/负面梗
  - 观察：冒犯率是否在自嘲开 + 中等负面时反转
```

## 7. 招募偏差控制

### 7.1 Round-05 渠道的偏倚诊断

Round-05 §10.3 列出了 5 个招募渠道，每个都有系统偏倚：

| 渠道 | 偏倚方向 | 对核心指标的影响 |
|:----:|:--------:|:---------------:|
| LOL 官方社区 | 高活跃度、高产品忠诚度 | **冒犯率↓** 理解正确率↑（铁粉更宽容） |
| NGA/虎扑/知乎 | 核心硬核玩家、社区文化沉浸深 | **冒犯率↓** 理解正确率↑ 但**对"错误使用梗"的冒犯率↑** |
| 游戏内推送 | 最真实但覆盖面偏向在线用户 | 偏倚最小，但**无法覆盖流失/轻度用户** |
| 大学生/LOL 高校群 | 年轻偏男性、社交活跃 | 分享意愿↑ 对梗的接受度↑ |
| 朋友圈/好友邀请 | 同质化严重 | **所有指标向朋友圈均值回归** |

### 7.2 偏倚控制的三层设计

```
第一层：招募描述中性化
  → 不说"LOL 梗称号测试"
  → 改为"LOL 游戏报告功能体验调研"
  → 不展示任何梗的预览（防止自选参与偏倚）

第二层：分层配额（在招募时强制）
  → 老玩家 ≤ 45%（防止过度代表）
  → 新玩家 ≥ 25%
  → 赛事观众 ≤ 35%
  → 自嘲开启用户：不强制配额，自由分布（因无法在招募时筛选）

第三层：事后加权（post-stratification）
  → 根据 LOL 官方用户画像（如有）对样本加权
  → 权重 = 总体比例 / 样本比例
  → 加权后的点估计 + bootstrap CI
```

### 7.3 无法消除的偏倚（须在报告中声明）

| 偏倚来源 | 为什么无法消除 | 对结论的影响 |
|----------|:-------------:|:-----------:|
| **幸存者偏倚** | 愿意填问卷的用户 ≠ 所有用户，流失玩家/非活跃玩家不会被覆盖 | 冒犯率可能被低估（不满的用户根本不理你） |
| **社会期望偏倚** | 用户在问卷中倾向于给出"更理性"的回答，真实产品中更情绪化 | 冒犯率可能被低估 5–10pp |
| **新玩家定义矛盾** | 真正的新玩家（< 6 个月）几乎不可能通过任何渠道招募 | 新玩家样本实际上是"玩了好几个月但不熟悉社区"的次新玩家 |

## 8. 停止规则：伦理与效率

### 8.1 逐梗序贯停止规则

对 T2（冒犯率），使用**序贯概率比检验 (SPRT)** 风格的提前停止边界：

```
每收集 25 份/梗后计算：

IF n ≥ 25 AND (观测冒犯数 n_offense / n) ≥ UPPER_BOUND(n):
  → 立即停止该梗的 T2 测试
  → 标记为 [EARLY_RED]
  → 不继续将高风险梗暴露给更多用户

IF n ≥ 50 AND (观测冒犯数 / n) ≤ LOWER_BOUND(n):
  → 继续测试但降低优先级的样本配额
  → 标记为 [EARLY_GREEN]
```

**停止边界**（基于二项精确检验）：

| n | 红色停止（冒犯数 ≥） | 绿色降优（冒犯数 ≤） |
|:--:|:--------------------:|:--------------------:|
| 25 | ≥ 7 (28%) | ≤ 1 (4%) |
| 50 | ≥ 11 (22%) | ≤ 3 (6%) |
| 75 | ≥ 15 (20%) | ≤ 5 (6.7%) |
| 100 | ≥ 18 (18%) | ≤ 6 (6%) |
| 150 | ≥ 25 (16.7%) | ≤ 10 (6.7%) |
| 200 | ≥ 31 (15.5%) | ≤ 13 (6.5%) |
| 250 | — | — (达到目标 n) |

**规则**：
- 任何梗在 n≥25 时达 RED → **立即停止**，标记，禁止出现在后续任何问卷中
- 任何梗在 n≥50 时达 GREEN → **降低配额优先级**，但不提前停止（因为可能需要亚组数据）
- 对照组梗（马头、及时雨送姜）**不适用提前停止**——它们的目的就是收集完整的冒犯率分布

### 8.2 全局停止规则

```
IF 本批次测试中 ≥ 3 个梗触发 EARLY_RED:
  → 暂停所有测试
  → 审查测试工具本身是否有问题（题面诱导、样本污染）
  → 不自动认为"梗有问题"，先排除方法学问题

IF 所有正常候选梗（排除对照组）在 n=100 时均为 GREEN:
  → 可提前结束测试
  → 但需补充声明"小样本通过不代表大样本安全"
```

### 8.3 对照组特殊规则

对照组（马头 V-18、及时雨送姜 V-17）用于**验证测试工具的灵敏度**——如果它们的冒犯率不高，说明测试工具失效：

```
IF V-17 或 V-18 在 n=100 时的冒犯率 < 15%:
  → 标记 [VALIDITY_WARNING]
  → 可能原因：样本偏差、提问中性化过度、用户不理解梗
  → 不依赖任何梗的冒犯率数据做决策，先排查工具效度
```

## 10. 执行建议与三档路线图

### 10.1 推荐路径

```
Phase A：低成本筛选（100份/梗 × 20梗 = 2,000份）
  ├─ 目标：淘汰明显问题梗，选出12–15个候选
  ├─ 输出：优先级排序 + 工具效度初步验证（用对照组）

  ├─ 目标：产品上线/下线决策
  ├─ 同时跑 T1+T2+T3（同批用户，Latin square）
  ├─ 输出：逐梗决策（GREEN/YELLOW/RED）+ CI 下限判断
  └─ 周期：2–3周

Phase C：T4/T5 A/B 测试（200份/组 × 6组 = 1,200份）
  ├─ 目标：展示方案优化
  ├─ 仅对 B 阶段通过的梗做
  └─ 可与 Phase B 并行

Phase D：真实灰度验证（产品内，Phase 4 灰度）
  ├─ 目标：自嘲开关真实效果 + 长期冒犯率

  └─ 输出：自嘲开关的 Phase 4 决策数据
```

## 12. 假设与局限

### 12.1 本校准的假设

| 假设 | 内容 | 如果假设被违反 |
|:----:|------|:--------------|
| A1 | T2 冒犯率可用二项分布近似（样本间独立） | 如果用户在社区中讨论测试 → 样本不独立 → 有效样本量降低 |
| A2 | 效应量 δ 的选择（5pp 冒犯率差异）是 clinically meaningful | 如果产品团队认为 3pp 也需要检测 → power 不足 |
| A3 | 问卷中的冒犯率与真实产品中的冒犯率呈正相关 | 如果相关弱 → 问卷数据对产品决策无意义 |
| A4 | 正态近似对 n≥50, p≈0.10 是合理的 | 对小 p 和极小 n 需使用精确检验（Fisher exact） |
| A5 | 20 梗的测试结果之间相关性低（多重检验校正有效的前提） | 如果梗高度相关（如左手/右手），Bonferroni 过度保守 |

### 12.2 本校准未覆盖

- **T4 A/B 测试的功效**（因 UI 测试的效应量取决于设计细节，无法先验计算）
- **T5 点击率的功效**（点击率基线未知）

## 附录 A：功效计算的 R/Python 参考代码

以下代码验证本文所有 n 计算，用户可自行修改参数：

```python
import math

# Standard normal quantiles (hardcoded from statistical tables)
Z = {
    '0.95': 1.6448536269514722,   # one-sided alpha=0.05
    '0.90': 1.2815515655446004,   # one-sided alpha=0.10
    '0.80': 0.8416212335729143,   # power=80%
    '0.60': 0.2533471031357997,   # power=60%
    '0.9975': 2.807033768343804,  # Bonferroni: alpha=0.05/20, one-sided
}

def sample_size_binomial(p0, p1, alpha=0.05, power=0.80):
    """单样本二项比例检验所需样本量（无连续性校正）"""
    alpha_key = f'{1-alpha:.4f}'
    power_key = f'{power:.4f}'
    # Map to our hardcoded z-values
    if abs(alpha - 0.05) < 0.001:
        z_alpha = Z['0.95']
    elif abs(alpha - 0.10) < 0.001:
        z_alpha = Z['0.90']
    elif abs(alpha - 0.0025) < 0.0001:
        z_alpha = Z['0.9975']
    else:
        raise ValueError(f'Unknown alpha: {alpha}')
    
    if abs(power - 0.80) < 0.001:
        z_beta = Z['0.80']
    elif abs(power - 0.60) < 0.001:
        z_beta = Z['0.60']
    else:
        raise ValueError(f'Unknown power: {power}')
    
    delta = abs(p1 - p0)
    n = (z_alpha * math.sqrt(p0*(1-p0)) + z_beta * math.sqrt(p1*(1-p1)))**2 / delta**2
    return math.ceil(n)

# 验证 T2 冒犯率
n_t2 = sample_size_binomial(p0=0.10, p1=0.15, alpha=0.05, power=0.80)
print(f"T2 冒犯率所需样本 (标准): n = {n_t2}")  # → 253

# 带 Bonferroni 校正
n_t2_bonf = sample_size_binomial(p0=0.10, p1=0.15, alpha=0.05/20, power=0.80)
print(f"T2 Bonferroni (20梗): n = {n_t2_bonf}")  # → 523

# T1 理解正确率
n_t1 = sample_size_binomial(p0=0.60, p1=0.50, alpha=0.05, power=0.80)
print(f"T1 理解正确率 (标准): n = {n_t1}")  # → 151

n_t1_bonf = sample_size_binomial(p0=0.60, p1=0.50, alpha=0.05/20, power=0.80)
print(f"T1 Bonferroni (20梗): n = {n_t1_bonf}")  # → 323

# Wilson CI
def wilson_ci(n, x, conf=0.95):
    """Wilson score interval for binomial proportion"""
    z = 1.959964  # two-sided 95%
    p_hat = x / n
    denom = 1 + z**2 / n
    center = (p_hat + z**2/(2*n)) / denom
    margin = z * math.sqrt(p_hat*(1-p_hat)/n + z**2/(4*n**2)) / denom
    return (center - margin, center + margin)

# 验证: n=250, 观测冒犯率 10%
ci = wilson_ci(250, 25)
print(f"Wilson 95% CI for 10% @ n=250: [{ci[0]:.1%}, {ci[1]:.1%}]")
# → [6.9%, 14.3%]

# 验证: n=500, 观测冒犯率 10%
ci = wilson_ci(500, 50)
print(f"Wilson 95% CI for 10% @ n=500: [{ci[0]:.1%}, {ci[1]:.1%}]")
# → [7.7%, 12.9%]

# FWER
fwer = 1 - (1 - 0.05)**20
print(f"FWER for 20 independent tests @ alpha=0.05: {fwer:.1%}")
# → 64.2%
```
